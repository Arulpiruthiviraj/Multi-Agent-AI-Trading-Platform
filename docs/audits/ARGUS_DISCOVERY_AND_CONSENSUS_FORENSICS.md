## 2. Root causes found (separate proven defects, none in the consensus arithmetic)

1. **Outcome-grading starvation (proven).** `PredictionOutcomeEvaluator` grades pending predictions oldest-first (`orderBy asc(timestamp)`), re-fetching weeks-old 1-minute windows through the serialized IBKR queue (research backfill, preempted by live work). Between 2026-09-17 and 2026-10-12 no per-agent outcome was written (only `consensus_debate_predictions`); on 2026-10-14 the grader processed 457 `agent_predictions` and 1,604 `kronos_predictions` outcomes, all from the **first two days** (2026-09-14..16) of a backlog of 308,635 Kronos and ~75k Technical predictions. The calibration table is therefore built from a frozen 2-day sample, with `evaluated_at` weeks after `timestamp`. Technical's "0.8 bucket: 1 sample" is a symptom, not a persistence bug in the table. *Not changed tonight* (see section 5).
2. **Clustered samples treated as independent (proven).** `agent_confidence_calibration` stores raw win/loss counts (written by `ReflectionEngine`), while `agent_performance_stats` already computes effective (clustered) counts: Kronos 1,496 predictions vs effective 111; Quant 59 vs 3; Technical 67 vs 5. The Beta-Binomial posterior mean is mathematically correct, but its inputs overstate certainty. Using effective counts moves Kronos 0.5108 -> ~0.55 (still far below 0.75) and Quant's 0.8 bucket 0.125 -> ~0.7, i.e. it removes confident-looking numbers in both directions rather than creating high confidence.
3. **Policy asymmetry (not an arithmetic defect).** The MODERATE tier (>= 0.6) requires a statistically validated calibration champion for every participating agent (`MODERATE_REJECT_UNTRUSTED_CALIBRATION`); the STRONG tier (>= 0.75) does not, and `calibrateConfidenceDetailed` falls back to the raw stated confidence when a bucket has no row (`NO_CALIBRATION_DATA`) and uses thin rows (< `minCalibrationSampleSize` 30) while only *labeling* them `INSUFFICIENT_CALIBRATION_DATA`. A stricter bar for the weaker tier than for the stronger tier is an inconsistency to decide on deliberately; it can only reduce approvals.
4. **Nondeterministic row choice (minor, code-proven).** `calibrateConfidenceDetailed` does `rows[0]` on `agent_confidence_calibration` filtered by agent and bucket but not by `provider`. Single-provider agents (Kronos, Technical, Quant: `provider = 'ALL'` only) are unaffected; NewsAgent has up to four rows per bucket (ALL plus per-provider) and the pick depends on row order.
5. **Kronos direction bias (observed).** 233,128 of 308,635 Kronos predictions (76%) are SELL, 57,477 BUY, 18,030 HOLD; the long-only desk can act on a Kronos SELL only with an existing position. Kronos therefore supplies BUY evidence on ~19% of rounds. Its forecast horizon is 5 ticks (`kronosTimeframe: tick`) while grading is a 5-minute wall-clock window (`kronosEvaluationHorizonMs`); the config comment states there is no clean tick-to-ms conversion. This mismatch is real but the horizon-sensitivity table above shows no horizon where Kronos beats a drift baseline, so correcting it is not expected to create edge.
