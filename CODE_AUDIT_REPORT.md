# Argus: Complete Codebase Architectural Audit

## Executive Summary
The Argus codebase is currently a functional prototype utilizing a mix of real AI interactions and mocked trading infrastructure. To transition into an AI-Native Autonomous Trading Operating System, significant architectural shifts are required to eliminate mocks, enforce strict Event-Driven communication, and implement a plugin-based provider system.

## 1. Disconnected Components & Mocks Identified
- **Market Data**: Currently uses `Math.random()` to generate price ticks and simulate volatility in `server.ts` (\`stepPortfolioPrices\`).
- **LLM Latency**: Simulates latency for fallback providers (OpenAI, Anthropic) using `setTimeout` and `Math.random()`.
- **Trading Execution**: Uses a fake `BrokerManager` that mocks order execution instead of connecting to a real broker API.
- **Charts & Statistics**: UI charts currently rely on the fake `equityHistory` generated by the backend loop.
- **Fake Timers**: Uses `setInterval` in `server.ts` to trigger simulated price updates and bot loops.

## 2. Architectural Violations
- **Coupling**: `server.ts` is overly large (3000+ lines) and contains routing, bot loop logic, database queries, and mock generation. It violates the Single Responsibility Principle.
- **Hardcoded Agents**: The Multi-Agent flow is hardcoded in a single pipeline rather than dynamically orchestrated through an EventBus.
- **State Management**: The global `tradingEngine.state` is mutated directly in `server.ts` rather than relying purely on SQLite as the single source of truth.

## 3. Recommended Remediation Plan
### Phase 2: Remove Mocks
- Delete all `Math.random()` price generation logic.
- Implement an empty/null state ("No Data") for charts when a live broker/data feed is disconnected.

### Phase 3 & 4: Unified Database & Startup
- Ensure all configurations (Risk, Broker, AI) are loaded directly from Drizzle ORM on boot.
- Implement an Intelligent Startup sequence checking database schema, API keys, and broker health before starting the terminal.

### Phase 5 & 6: AI Router
- Fully modularize the `AIRouter.ts` to support dynamic fallback, cost tracking, and provider health checks via SQLite.

### Phase 7: Broker Engine
- Implement a `BrokerPlugin` interface.
- Add an `AlpacaBroker` plugin to handle real paper trading.

### Phase 8: EventBus
- Migrate all internal communication in `server.ts` to a robust `EventBus` to decouple the bot loop from the Express server.
